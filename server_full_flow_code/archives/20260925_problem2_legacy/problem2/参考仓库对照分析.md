## 3. YeexiaoZheng：有效思路是预训练特征与融合方式的比较

最佳模型OTEModel用文本预训练模型的pooler输出，以及ResNet50的全局图像特征，各投影到64维，拼接后经过TransformerEncoderLayer和分类头。Trainer对预训练骨干和新增模块设置不同学习率。该项目含文本单模态、图像单模态和融合消融；OTE的文本单模态71.875%、图像单模态63%、融合74.625%，支持“融合在这组实验中有收益”，但不能直接证明收益来自跨模态注意力。

原因可从[OTEModel.py](https://github.com/YeexiaoZheng/Multimodal-Sentiment-Analysis/blob/3745ef924f800dd462cddd2179d09c11cca9f140/Models/OTEModel.py)看出：两个 `[B,64]` 表示unsqueeze后沿特征轴拼接成 `[1,B,128]`。默认Transformer以第一维为序列，长度只有1，所以注意力在单个key上归一化，权重恒为1。层内投影、残差、前馈网络仍有作用，但不是两个模态token之间的选择性注意力。其真正交叉注意力模型CMAC的README结果反而是67.1875%，低于简单融合。

可以借鉴的模块：

1. 模态先独立汇聚，再做全局融合，降低对精确词帧对齐的依赖。本任务可汇聚音频、视觉有效槽，再与句级文本融合。
2. 骨干和融合头分组学习率。当前LoRA已控制可训练规模，不必为了模仿仓库而全量解冻。
3. 单模态与融合的同划分消融，用实际增益判断音视频是否有用。

若实现真正的模态token注意力，应构造 `[B,3,d]` 并设置 `batch_first=True`，沿三模态轴计算注意力，显式处理缺失模态。不能照搬上述长度1的输入形状。部分简单融合代码把softmax概率再次送入交叉熵；迁移时应保留原始logits交叉熵定义。

## 4. CodeREWorld：先单模态训练，再用序列上下文融合

[run.py](https://github.com/CodeREWorld/Multimodal-Sentiment-Analysis/blob/5abac2033e55dfe9650f907b11394b43d89cc962/run.py)先分别训练text/audio/video并保存中间激活，再训练多模态模型。[model.py](https://github.com/CodeREWorld/Multimodal-Sentiment-Analysis/blob/5abac2033e55dfe9650f907b11394b43d89cc962/model.py)虽然类名为LSTM_Model，主体实际使用BiGRU，随后用全连接网络分类，可选时序注意力。mask用于去除padding对损失和准确率的影响。

这里的上下文序列按视频/对话组织话语，不等价于本项目单条样本内的50个槽，也不能将任意batch中的相邻样本当上下文。只有在原始视频ID、真实时间顺序可恢复且数据划分保持隔离时，才能迁移跨话语上下文模型。

两点必须区分：

- 代码每轮读取测试标签评价，并记录最高test accuracy以及最低test loss对应结果；[结果截图](https://github.com/CodeREWorld/Multimodal-Sentiment-Analysis/blob/5abac2033e55dfe9650f907b11394b43d89cc962/result.png)不能作为“按valid冻结后一次测试”的等价证据。截图未标数据集和类别数，不能断言其约77%就是MOSEI三分类。
- 可选 `self_attention` 将模态评分做成 `[B,3,1]`，却对最后长度1的轴softmax，导致每个权重恒为1，实际相加而非归一化的模态选择。若迁移应沿模态轴归一化。该分支是否启用取决于运行参数，不能据此推断截图使用了它。

原项目依赖旧TensorFlow接口，适合迁移算法思想到现有PyTorch环境，不宜直接引入其完整运行栈。

## 5. 对当前模型最值得做的进一步改进

本次不新增未经训练验证的正式模型。前次注意力试验valid降至66.3462%，已经归档；当前保留test达标的模型。

优先考虑**单模态辅助监督 + 句级质量门控融合**，而非再次堆叠注意力层：

先对每个模态有效表示做带掩码汇聚，得到 $z_m$，训练独立分类头 $\ell_m=C_m(z_m)$。辅助损失为

$$L_{aux}=\sum_m\eta_m\,\mathrm{CE}(\ell_m,y),$$

仅对存在有效观测的样本模态计入，防止音视频分支完全依赖文本而不学习自身信号。由质量统计和模态表示预测门控分数，并在可用模态集合 $\mathcal A$ 上归一化：

$$g_m=\frac{\exp s_m}{\sum_{j\in\mathcal A}\exp s_j},\qquad
\ell=\sum_{m\in\mathcal A}g_m\ell_m+R(z_T,z_A,z_V).$$

这是待验证的候选方案，不能把公式写成已部署实现或已取得提升。残差 $R$ 可沿用小型交互模块；文本先验与文本分类头须合并设计，避免重复加入同一证据。全缺失输入需单独约定退化输出。新增非线性门控也会改变问题三的原生加性账本，因此若候选获胜，必须同步重推账本及验证重建；8子集Shapley仍可重新计算。

有顺序元数据时，再单独比较跨话语BiGRU；最后才比较正确维度的三模态token注意力。每次只改变一个机制，保持相同划分、训练预算和随机种子，以valid Accuracy为主、Macro-F1及中性类召回为辅助，并检查缺失场景退化。无验证增益则保留现有模型，不把失败分支并入正式路径。

不能承诺下一轮一定到75%。在727条测试样本上，达到75%至少需546条正确，相比现有514条还需净增加32条；这需要可验证的泛化增益。
