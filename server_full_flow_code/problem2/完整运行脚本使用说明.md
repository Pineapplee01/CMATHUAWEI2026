# 问题二完整运行脚本使用说明

唯一正式方案统一称为“问题二正式模型”，定义在 `problem2/model.py`，类名 `Problem2Model`，新配置标识 `architecture=problem2`。已有正式.pt保持原样，由加载接口兼容其历史标识。Macro-F1、中性F1是指标名称，与模型命名无关。

总脚本位于项目根目录：`run_problem2.py`。它调用现有模块组织完整流程，不复制模型或训练代码。

## 1. 一条命令执行完整流程

```bash
cd /user_home/gaojianan/CPMCM
conda activate CPMCM
python run_problem2.py
```

默认使用cuda:3及训练seed 2026、2027、2028、2029、2030，按顺序执行：

1. 代码单元/集成检查，失败立即停止。
2. 加载正式权重，评估完整test、局部30%缺失参考以及252组连续缺失test场景。
3. 评估完整valid、局部30%缺失valid以及168组验证集连续缺失场景。
4. 使用正式权重生成附件3的30条预测和提交核验记录。
5. 六组研究消融：每seed五次训练，完整/缺失基线共用权重；共25次训练。每次先用valid选择epoch，再评估test场景，最后汇总指标并生成六张PNG/PDF论文图及图注。

正式权重是 `AAAmodel/checkpoints/problem2_aligned.pt`，不会被研究组自动替换。正式权重的训练seed仍为2026；总脚本的 `--seeds` 控制新研究实验，不会把已有正式模型伪装为五seed结果。若要重新训练正式架构，使用同一入口的 `--mode train`。

## 2. 常用命令

```bash
# 明确指定五个seed与实验名称
python run_problem2.py --seeds 2026 2027 2028 2029 2030 --run-name paper_run

# 只使用一个训练seed，但保留全部实验组与场景
python run_problem2.py --seeds 2026 --run-name paper_single_seed

# 选择GPU
python run_problem2.py --device cuda:0 --run-name paper_gpu0

# 仅检查正式模型：不训练六组研究模型
python run_problem2.py --mode formal --run-name formal_check

# 仅跑六组研究实验和绘图
python run_problem2.py --mode ablation --run-name ablation_only

# 查看执行计划，不创建目录、不启动计算
python run_problem2.py --dry-run

# 端到端联调：正式模型仍全量评估，只有研究实验缩为小样本一轮
python run_problem2.py --smoke --run-name pipeline_check
```

`--smoke`的消融输出目录自动增加 `_smoke`，只训练第一个seed，使用48条train、16条valid、16条test；图表带明显水印，不能作为论文实验成绩。

## 3. 中断后继续

保留原命令参数并增加 `--resume`：

```bash
# 例如先前使用单seed配置
python run_problem2.py --seeds 2026 --run-name paper_single_seed --resume

# 默认五seed实验中断后
python run_problem2.py --resume
```

总脚本跳过已成功完成的阶段；消融阶段还会跳过已完成且权重身份核验通过的模型。未完成的训练从头重跑，不恢复优化器中间状态。阶段状态保存在pipeline.json；失败详情同时写入阶段日志。

同名目录禁止静默覆盖。配置、源代码、正式权重或输入数据改变后，应使用新的run-name，不能把不同协议混入同一份统计结果。若先前指定了自定义seed、模式、配置或GPU，恢复时也应指定相同参数。

## 4. 输出位置

以 `--run-name paper_run` 为例：

| 内容 | 路径 |
|---|---|
| 总执行状态、配置快照、运行摘要 | `problem2/results/full_runs/paper_run/` |
| 每阶段日志 | `problem2/results/full_runs/paper_run/logs/` |
| 正式模型预测、指标、252组test及168组valid场景 | `problem2/results/full_runs/paper_run/formal/` |
| 正式模型混淆矩阵、残差与缺失规律图 | `problem2/results/full_runs/paper_run/formal/figures/` |
| 六组研究实验汇总与逐seed结果 | `problem2/results/ablations/paper_run/` |
| 六张论文图（PNG/PDF） | `problem2/results/ablations/paper_run/figures/` |
| 各seed研究检查点 | `AAAmodel/checkpoints/ablations/paper_run/` |

完成后优先阅读总目录的 `运行结果.md`，然后阅读消融目录的 `实验报告.md`、`图表说明.md`。逐seed指标在 `primary_by_seed.csv`，均值/标准差在 `primary_summary.csv`。每组的原始逐样本预测与实际缺失区间也保留，便于复查。

如仅需根据既有消融数据重新绘图，不重训：

```bash
python -m problem2.ablation --plots-only --run-name paper_run
```

## 5. 配置项

默认消融配置为 `configs/problem2_ablation.json`，可通过 `--config <文件>` 替换。

- `seeds`、`device`可被同名命令行参数覆盖。
- `epochs`、`patience`控制各研究组的相同训练预算。
- `main_rate`控制主消融和位置分析的缺失跨度。
- `rates`控制鲁棒性曲线横轴。
- `mask_seeds`控制随机连续区间重复，与训练seed分开。
- `consistency_weight`、`reconstruction_weight`控制研究模块损失系数。

模型细节及实验解释边界见[消融实验说明](消融实验说明.md)。研究全模块组新增的一致性和重构监督，不等于当前正式模型已经包含这些训练目标。

## 正式模型测试集场景覆盖

测试集默认完整评估七种缺失组合（T/A/V/TA/TV/AV/TAV）、六种连续跨度（10%/20%/30%/40%/50%/70%）以及开头、中部、结尾、随机位置。随机位置重复3个固定掩码seed（2026、2027、2028），其他位置各1次，共252组，每组727条；另保留完整输入及原随机TAV30%参考。

验证集保留原168组协议。两种划分分别保存，避免互相覆盖：

- `formal/test_scenarios/local_scenarios.csv`：252组测试指标。
- `formal/valid_scenarios/local_scenarios.csv`：168组验证指标。
- 各划分的 `predictions/`：逐场景预测与实际缺失区间。
- 各划分的 `position_effects.csv`、`duration_effects.csv`、`overall_by_rate.csv`：不同聚合层级的全部指标。
- `formal/figures/test/`、`formal/figures/valid/`：独立的缺失曲线。

每组报告ACC、Macro-F1、Weighted-F1、中性Precision/Recall/F1、MAE、Pearson及输出一致性；另存实际删除的观测比例。完整输入成绩不混入缺失平均。正式模型沿用每模态自身槽轴的连续区间协议，联合随机缺失起点按模态独立抽取；不将其描述为严格同步缺失。

直接运行正式评估入口时，test也默认开启全部252场景：

```bash
python -m problem2.problem2 evaluate --split test --frozen-test --device cuda:3
```

总脚本推荐用新运行名启动更新后的协议：

```bash
python run_problem2.py --mode formal --run-name formal_test_complete
```

代码和协议改变后不能复用旧总脚本的已完成标记；请使用新run-name。评估期间权重身份固定，结果不会反过来选择训练epoch。

## 6. 唯一入口与运行模式

项目根目录只保留 `run_problem2.py`，不再保留另一个总脚本。模式如下：

| 模式 | 用途 |
|---|---|
| 默认 / `--mode full` | 代码检查、252组test、168组valid、附件3、五seed六组消融与绘图 |
| `--mode formal` | 正式权重完整评估与附件3预测，不训练 |
| `--mode ablation` | 六组研究实验与绘图 |
| `--mode train` | 自选seed重新训练正式架构，独立保存实验权重 |

```bash
# 正式架构训练
python run_problem2.py --mode train --seed 2026 --run-name official_training

# 训练专用参数说明
python run_problem2.py --mode train --help

# 恢复训练实验（路径参数）
python run_problem2.py --mode train --resume problem2/results/runs/official_training
```

训练实现保存在 `problem2/experiments.py`，作为内部模块调用，不是另一个用户运行入口。训练模式使用原有训练参数；完整/评估/消融模式仍使用本页介绍的参数。完整流程的 `--resume` 为布尔开关，训练模式的 `--resume` 后接已有实验目录。

## 7. 原生未对齐数据（50/500/500）

使用同一总入口的训练模式，并显式指定未对齐配置：

```bash
python run_problem2.py --mode train --config configs/problem2_unaligned.json --seed 2026 --run-name unaligned_soft_attention_seed2026
```

数据来自 `AAAdata/Appendix_2/标准化/未对齐版本/processed_po`，不会误用同名的对齐版目录。该配置启用软注意力对齐，训练后自动评估完整/局部30%test和全部252组test场景。结果写入 `problem2/results/runs/<run_name>/processed_po_seed<seed>/`，不写入已有正式模型的结果目录。默认 `--mode full/formal` 仍针对已采用的对齐模型；不要把该默认评估当作未对齐新模型成绩。

模型及公式见[未对齐数据软注意力方案](未对齐数据软注意力方案.md)。未对齐checkpoint使用独立格式标识，通过相同restore接口加载。
